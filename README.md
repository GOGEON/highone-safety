## 프로젝트 개요

스키장 사고는 특정 시간대와 혼잡 조건에 집중되지만, 이용객은 자기가 가는 시간이 얼마나 붐비고
위험한지 미리 알 방법이 없습니다. 이미 축적된 사고·발매 데이터를 **예방 정보로 되돌리는 것**이
이 프로젝트의 목표입니다.

### 데이터에서 확인한 것

| 발견 | 근거 |
|---|---|
| 하루는 두 번 위험해진다 | 사고가 11시(66건)와 15시(89건)에 몰려 전체의 28%를 차지 |
| 붐빔과 위험은 다르다 | 3월 발매량은 1월의 12%에 불과하지만, 1,000매당 사고는 3.06건으로 1월(2.67건)보다 14% 높은 시즌 최고치 |
| 요일이 위험을 바꾼다 | 토요일 일평균 3,073매 — 화~목 평균(1,299매)의 2.37배 |
| 17시는 안전한 게 아니다 | 주간→야간 전환 정비 시간대라 이용 자체가 없음. 추천에서 제외 처리 |

## 주요 기능

1. **시간대별 혼잡·위험 예보** — 월·요일을 고르면 09~22시 위험지수(0–100)와 3단계 신호등 제공
2. **사고 패턴 차트** — 시간대·월별 분포, 이용량 대비 사고율, 월×시간대 히트맵
3. **방문 추천** — 주간/야간 각각의 최저 위험 시간대와 피해야 할 시간대
4. **운영자용 배치 제안** — 사고 다발 상위 5개 시간대와 누적 커버율, 배치 등급

### 위험지수 산출식

```
위험지수 = 시간대 사고지수 × (1 + 0.5 × (혼잡계수 − 1)) × 월 사고율계수
         (전체 조합의 최댓값을 100으로 정규화, 등급 경계 30점·58점)

시간대 사고지수 = 시간대별 사고건수를 최댓값 100으로 정규화
혼잡계수       = 월 혼잡계수 × 요일 혼잡계수 (리프트권 일평균 발매량 기준)
월 사고율계수   = (월 사고건수 ÷ 월 발매량) ÷ 전체 평균 사고율
```

혼잡을 그대로 곱하지 않고 **0.5로 감쇠**시킨 것이 이 모델의 핵심입니다. 붐빔은 사고의 *노출량*을
늘리지만 개인이 다칠 *확률*과 1:1로 비례하지 않습니다. 혼잡을 그대로 곱하면 "한산하지만 사고율이
가장 높은 3월"이 안전한 달로 잘못 표시됩니다.

### 알려진 한계

- 리프트권 발매량은 **일 단위**라 시간대별 실이용객 수를 알 수 없습니다. 그래서 시간대 축은 사고
  절대건수로만 구성했고, 혼잡 보정은 일 단위(월·요일)에만 적용했습니다.
- 사고 데이터에 **부상 정도·사고 유형이 없어** 모든 사고를 동일 가중으로 계산했습니다.
- 계절기상 정보는 **2017–2019년** 자료로 사고·발매(2024년)와 연도가 달라 위험지수 계산에는 넣지
  않았습니다. 3월 해빙–결빙 해석의 **정황 근거**로만 제시합니다.

## 디자인

동일한 분석 결과 위에 네 가지 디자인 방향을 만들어 비교한 뒤, **예보형(날씨앱 문법)을 최종
디자인으로 확정**했습니다. 큰 신호등과 가로 시간대 스트립으로 "지금 가도 되나"를 스크롤 없이
답하는 구조로, 모바일의 일반 이용객에게 가장 잘 맞습니다.

- `index.html` — **최종 서비스** (예보형)
- `compare.html` — 검토 과정에서 만든 디자인 시안 4종 비교 허브 (기록용)

검토한 시안: 분석 로직·데이터·문구는 `shared/` 모듈을 공유하므로 **달라지는 것은 정보 위계와 색 테마뿐**입니다.

| 시안 | 방향 | 특징 | 타깃 |
|---|---|---|---|
| **A (확정)** | 예보형 | 날씨앱 문법, 큰 신호등 + 가로 시간대 스트립 | 일반 이용객 (모바일) |
| [B](designs/b-control.html) | 관제형 | 다크 콘솔, KPI 타일 + 배치표 전면, 고밀도 | 운영자 |
| [C](designs/c-editorial.html) | 에디토리얼 | 스위스 타이포, 번호가 붙은 5개 장의 논증 구조 | 심사·리뷰 |
| [D](designs/d-retro.html) | 레트로 | 스키 포스터, 굵은 테두리와 스티커 배지 | 20~30대 · SNS |

## 실행 방법

빌드 도구나 패키지 설치가 필요 없는 **순수 정적 사이트**입니다.

```bash
python -m http.server 8000
```

브라우저에서 `http://localhost:8000` 접속. (`file://`로 직접 열어도 동작하지만, 배포 환경과 같은
조건에서 확인하려면 위 방법을 권장합니다.)

### 데이터 갱신

원본 CSV에서 `data/dataset.json` / `dataset.js`를 다시 만들려면:

```bash
python tools/build_data.py
```

## 접근성·구현 메모

- **색만으로 의미를 전달하지 않습니다.** 3단계 신호등은 항상 기호(✓ / ! / ✕)와 등급 이름을
  함께 표시합니다. 적록색약 시뮬레이션에서 녹색과 빨간색의 색차가 작기 때문입니다.
- **모든 차트에 표 보기가 있습니다.** 툴팁이 값에 접근하는 유일한 통로가 되지 않도록 했습니다.
- **차트는 컨테이너 실제 픽셀 폭으로 그립니다.** viewBox만 늘려 축소하면 모바일에서 축 라벨이
  읽을 수 없게 작아지므로, `ResizeObserver`로 폭이 바뀔 때마다 다시 그립니다.
- **이중 축(y축 2개) 차트를 쓰지 않았습니다.** 사고건수와 사고율처럼 단위가 다른 값은 축을
  공유하지 않고 차트를 나눴습니다.
- **API 실시간 호출이 없습니다.** 공공데이터포털 CSV를 미리 가공해 저장소에 포함하는 정적 데이터
  방식이라, 배포 후 CORS·혼합 콘텐츠·인증키 문제가 발생하지 않습니다.
